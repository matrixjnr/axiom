# Changelog

## Unreleased

- Make `Request` an immutable final class, preserving its constructors, factories, accessors and withers. Pre-release record patterns and `java.lang.Record` consumers must migrate to named accessors. Preserve metadata equality and fix hashing for equal requests whose header names differ only in case.
- Refresh the Axiom logo with custom vector lettering and light/dark README variants. Clarify why the OpenAPI example appears under two Swagger UI tags, with checks for both generated formats. Accept Windows line endings in documentation front matter and keep OpenAPI golden files at LF for deterministic comparisons.
- Add optional native transports for HTTP listeners. `ListenerOptions.transport(TransportKind)` selects `AUTO` (the default), `NIO`, `EPOLL` or `KQUEUE`: `AUTO` uses epoll or kqueue when Netty's native library is on the class path and usable and NIO otherwise, and an explicit native kind that is not usable fails startup with an `IllegalStateException` before any socket exists. The native artifacts (`netty-transport-native-epoll`, `netty-transport-native-kqueue`, with the platform classifier) are optional runtime dependencies that `axiom-http` does not require or publish; applications that add nothing run on NIO as before. Checksums for their jars (linux-x86_64, linux-aarch_64, osx-x86_64, osx-aarch_64) and POMs are in the dependency verification metadata. The `axiom-http` integration tests, including TLS, lingering, shutdown and backpressure, now also run on the native transport of the build platform (`integrationTestNative`; `-Daxiom.requireNativeTransport=true` makes an unusable native transport a failure instead of a skip). io_uring is evaluated and not supported. See `docs/http.md#native-transports`.
- Add JMH benchmarks for the lock-free request path and request ID generation under several threads (`RequestPathBenchmark`, `RequestIdBenchmark`) and for the dispatch overhead of 0, 1, 5 and 20 middleware, global or on the route, with allocation per request through `-prof gc` (`MiddlewareChainBenchmark`). They compile in `check` and run only on request. `docs/benchmarks.md` gains the run commands and a methodology note; no results are published.
- Add the opt-in `axiom-openapi-ui` module: `SwaggerUi.builder().spec(name, url).build().register(app, middleware...)` serves Swagger UI from the application (default `/docs`) and points it at your OpenAPI or Swagger document(s). The UI files come from the `org.webjars:swagger-ui` WebJar (pinned, checksummed), are read once and served from memory; nothing is loaded from a CDN. The page has no inline script, the generated initializer names only same-origin document paths, every response carries a strict `Content-Security-Policy` (`script-src 'self'`, `connect-src 'self'`, no framing), `nosniff` and `no-referrer`, assets sit under a versioned path with immutable caching and strong ETags, and file names are looked up in a fixed table so path traversal cannot reach anything else. Nothing is served unless `register` is called, and it takes route middleware so the UI can sit behind the same policy as the documents. See `docs/openapi.md`.
- Add the opt-in `axiom-openapi` module: `OpenApi` renders an OpenAPI 3.1 document, or the equivalent Swagger 2.0 document, from an application's routes and their `RouteDoc` descriptions, and `serve`/`serveSwagger` register a route that serves the document rendered once (cached, with an `ETag`), only when called. Schemas are generated for records, JavaBean and Lombok-style classes (property names follow the JSON codec, including Jackson's `@JsonProperty`/`@JsonIgnore` when present), enums, primitives, `java.time`, collections, arrays, maps and `Optional`, with cycle and depth bounds; built-in validation rules become schema constraints. Unsupported types, unknown security schemes, duplicate operation ids and ill-fitting rules fail at build time with the route in the message. Output is deterministic. `RouteDoc.type` and `listOf` build generic types. See `docs/openapi.md` and `examples/openapi`; the `docs/openapi.md` examples are checked against the compiled sources like the README's.
- Add optional route metadata: `RouteDoc` (summary, description, tags, operation id, parameters, request body, responses, security scheme names, deprecated, hidden) attached with `Application.describe(route, doc)` and read with `Application.doc(route)`. It is plain data with no annotations or scanning and never affects routing. **Binary incompatible (pre-release):** `Application` gained `describe` and `doc`. See `docs/routing.md`.
- Describe built-in validation rules as data: `Rule.constraint()` returns a `Constraint` (kind, bounds, pattern, allowed values; empty for custom rules) and `Rules.constraints()` collects the constraints of `field` and `each` steps by property, so tools can mirror a rule set without parsing predicates. See `docs/validation.md`.
- Add cookie-based browser security to `axiom-security`. `RateLimit` middleware (token bucket or sliding window, per-key budgets from a pluggable `RateLimitKey`: peer address, trusted-proxy client address or principal) tracks at most `maxKeys` keys with least-recently-used eviction, uses an injectable clock, answers 429 `rate_limited` with `Retry-After`, optionally adds the IETF `RateLimit-*` headers and records bounded-tag metrics. `Sessions` provides server-side sessions with a `SessionStore` SPI and a bounded `InMemorySessionStore` (idle and absolute timeouts, anonymous-first eviction), 256-bit random identifiers that rotate at sign-in, atomic transactional writes and a `SessionAuthenticator` for the existing `Security` policies. `Cookies` parses the `Cookie` header strictly and `SetCookie` builds `Secure; HttpOnly; SameSite=Lax` cookies with `__Host-`/`__Secure-` rules. `Csrf` protects unsafe methods with a per-session synchronizer token or an HMAC-signed double-submit cookie, plus `Sec-Fetch-Site` and `Origin` checks, answering 403 `csrf_rejected`. See `docs/security.md` and `examples/browser-app`.
- Add a read-only hook for the listener's own error responses: `ListenerOptions.Builder.rejectionObserver(RejectionObserver)`. It is called with the status, problem code and request ID of each 400, 408, 413, 414, 417, 431, 501, 503, 504, 505 and listener-generated 500 just before the response is written, never with request content, cannot change the response, and a failing observer is logged and ignored. See `docs/errors.md#observing-listener-rejections`.
- Add `TestClient.startMappingFailures(app)`, which answers a handler exception that nothing maps, and a response the transport could not send, with the listener's generic 500 problem response (`Connection: close`, logged at ERROR) instead of propagating. `TestClient.start(app)` keeps propagating them for debugging. A parity test compares the client with a live listener. See `docs/errors.md#testing-failures`.
- Add the opt-in `Application.developmentErrors()`: problem responses for failures the runtime builds, and the 500 for an exception nothing maps, carry a `debug` member with the exception's class, message, up to 64 stack frames and up to 8 causes. It is off by default and has no configuration flag, `listen` refuses any non-loopback address while it is on, and a warning is logged at startup. Default responses stay opaque and tests pin that. **Binary incompatible (pre-release):** `Application` gained `developmentErrors()`. See `docs/errors.md#development-errors`.
- Add `Context.problem(AxiomException)`, which builds the standard problem response (status, typed headers, `application/problem+json`, status, code, request ID and violations) so an error handler can decorate it instead of replacing it. The method is a default method, so existing `Context` implementations keep compiling. See `docs/errors.md`.
- Add group-scoped error handlers: `RouteGroup.error(type, handler)` registers a handler for a group and its nested groups. Resolution is inner scope first (the group of the matched route, each enclosing group, then the application); handlers of a group that fails to configure are removed with it. **Binary incompatible (pre-release):** `RouteGroup` gained `error`. See `docs/errors.md#group-scoped-handlers`.
- Close the connection after every 500 the framework generates. The generic 500 after a failing error handler now carries `Connection: close` (the listener's own 500 for an unmapped exception already closed); a 500 the application chooses, such as `InternalServerErrorException`, still keeps the connection alive. Wire tests cover each path. See `docs/errors.md#framework-statuses`.
- Decide that error handler responses are never subject to Accept negotiation: an error is not answered 406, while a successful response of the same type is. The rule is documented in `docs/errors.md` and pinned by tests.
- Let middleware decorate responses produced from exceptions. `Middleware.afterError(context, response)` (default: unchanged) is called, innermost first, for each middleware that was entered when a problem response, an error handler response, the generic 500 or the 406 was produced, so headers no longer disappear on error responses. `SecurityHeaders` and `Cors` use it. Error mapping now runs in an outer step of each route's chain, which also makes custom `notFound`/`methodNotAllowed` handler exceptions decorated by global middleware. See `docs/middleware.md`.
- Make the logging of mapped failures configurable and log each failure once. `Application.failureLog(logger, level)` chooses the `System.Logger` (default name `com.jsgalactic.axiom.failures`, previously the name of an internal class) and level (default WARNING, `OFF` silences); a failing error handler is always logged at ERROR. An error handler that translates a failure into a 5xx `AxiomException` no longer logs twice. **Binary incompatible (pre-release):** `Application` gained `failureLog(System.Logger, System.Logger.Level)`. See `docs/errors.md#logging-of-failures`.
- Trace context: `tracestate` is parsed strictly (`TraceState`, at most 32 members and 512 characters, all-or-nothing) and carried in `TraceContext.traceState()` and by `child()`; `TraceContext.headers()` lists the headers for an outgoing call. The framework's own log messages about a request include `trace=<trace id>` next to the request ID when the caller sent a valid `traceparent`; `Context.correlation()` gives applications the same text without a thread-local map; `app.use(TraceContext.responseHeader())` opts in to a `traceresponse` response header. **Binary incompatible (pre-release):** `TraceContext` gained a fourth record component (`traceState`; the three-argument constructor remains). See `docs/observability.md`.
- Health: a startup probe (`Health.Builder.startup`, `GET /health/startup`, UP for good once its checks pass), per-check timeouts (`liveness`, `readiness` and `startup` overloads taking a `Duration`) and result caching (`Builder.cacheFor`, at most one minute). Draining is now automatic on JVM shutdown: `Application.closeOnJvmShutdown(Duration drainDelay)` runs the actions registered with the new `Application.onDrain` (a `Health` registers `beginDrain` itself), waits the delay for the balancer to notice, then closes the application; `closeOnJvmShutdown()` keeps its behavior. **Binary incompatible (pre-release):** `Application` gained `closeOnJvmShutdown(Duration)` and `onDrain(Runnable)`. See `docs/observability.md`.
- More metrics: `ListenerOptions.name` names a listener and tags its connection series with `listener`; new series `axiom.http.connections.accepted` and `.rejected` (reason `limit` or `shutdown`), `axiom.http.listener.bytes` (direction `in` or `out`, wire bytes including TLS), `axiom.http.listener.answers` (responses given before admission, by status) and `axiom.codec.duration` and `axiom.codec.failures` (by operation and the media type the codec declared). **Behavior change (pre-release):** the existing `axiom.http.connections` gauge gains the `listener` tag. See `docs/observability.md`.
- Streamed responses: `Response.withStreamLifetime(Duration)` gives one stream its own lifetime (at most one day) instead of the request deadline, which stays unchanged for other requests; `Response.onStreamEnd` and `Response.mapStream` let middleware observe how a stream ended (`StreamOutcome`: completed, client disconnected, limit exceeded, timeout, shutdown, failed, with bytes and elapsed time) and wrap its body; closing a listener now lets open streams keep the shutdown grace period and tells them with `BodyWriter.shutdownRequested()` and `onShutdown`, so a body can end normally with a final chunk, while one still running when the period ends is cut as before; the four stream metrics gain `method` and `route` tags (the dispatcher's bounded endpoint set) and `TestClient` records them; `TestClient.start(app, StreamBuffering)` models the listener's water marks, 16 KiB pieces and stall bound, and `StreamedResponse.beginShutdown()` plays the shutdown signal. **Behavior change (pre-release):** streams were cancelled the moment a listener closed. See `docs/streaming.md`.
- `MetricsRegistry.builder()` configures histogram buckets for all timers or for one timer name (`timerBuckets`), the series limit and `# HELP` text (`help`); `MetricsRegistry.create()` is unchanged and `DEFAULT_BUCKETS` documents its bounds. `PrometheusText` writes `# HELP` lines (the runtime's own metrics have built-in text) and exposes the registry's size and refused series as `axiom_metrics_series` and `axiom_metrics_dropped_series_total`. Quantiles and exemplars deliberately stay out of the registry; see `docs/observability.md`.
- Add a documentation site built with Jekyll and the `just-the-docs` theme from `README.md` and `docs/*.md` (left navigation tree grouped into Getting started, Guides and Operations, search, light and dark colour schemes, code copy buttons, versioned footer), plus the aggregated Javadoc of the published modules under `/api/`. The Markdown stays the single source: `docs/*.md` gained a three-field front matter, and `./gradlew jekyllSource` assembles the Jekyll source. Ruby gems are pinned with hashes in `site/Gemfile.lock` and installed frozen in CI; the theme's assets and the search index are served from the site, with no CDN. `check` now fails on a broken link or anchor in the Markdown (`checkDocsLinks`) and on a page without front matter, and CI checks the built site (`checkSiteLinks`). A new Docs workflow builds the site for pull requests and deploys it to GitHub Pages from `main`. See `docs/site.md`.
- Make CI supply-chain checks stricter. The `commits` job now reports every failing commit instead of stopping at the first, lists the commits it did not build in a warning when a series exceeds 20, and builds only the tip of `dependabot/` branches. Dependabot also updates `build-logic` and the `compatibility/` consumers. `.github/scripts/verify-pom-checksums.py` fails the `build` job when a component with a `.module` lacks its `.pom` checksum (or adds them with `--fix`); 36 missing POM checksums were added to the three verification metadata files. The trust model and review of metadata changes are documented in `docs/releasing.md`.
- Confirm the path and wildcard policy as the long-term contract and write migration notes in `docs/routing.md#path-policy`: paths with empty or dot segments, backslashes, NUL or encoded separators stay 400, matching stays exact (trailing slashes distinct, case-sensitive, no redirects), with a table of what to do for applications that relied on a normalizing router. A new `PathPolicyTest` pins the matching rules.
- Document why `maxRequestBody` stops at 64 MiB (bodies are held in memory and the ceiling equals the default `maxInFlightBodyBytes`, so every permitted body fits the default budget) and keep the range deliberately; larger uploads need a streaming path.
- Decide `Accept` negotiation: a 406 is now answered only for safe methods (`GET`, `HEAD`, `OPTIONS`, `TRACE`). For `POST`, `PUT`, `PATCH`, `DELETE` and extension methods `Accept` is advisory and the handler's response is always sent, so a handler can no longer create a resource and then answer 406 to a client that then retries. Route declarations have no representations to negotiate against before the handler runs, so a handler that must refuse checks `ctx.header("Accept")` and throws `NotAcceptableException` itself. **Behavior change:** unsafe-method requests whose `Accept` excluded the response were answered 406 before. See `docs/bodies.md#accept-negotiation-406`.
- Accept absolute-form request targets (`GET http://host/path?q=1`) on the listener, as RFC 9112 section 3.2.2 requires of an origin server, for every method. The scheme (`http` or `https`) and authority are checked and dropped; the path and query then pass the usual path rules. The authority must be a valid host without user information and must equal the `Host` header ignoring case (an HTTP/1.0 request without `Host` is accepted on the authority alone); an empty path becomes `/`. A mismatch, another scheme, a fragment or an unsafe path is still answered 400. **Behavior change:** such requests were answered 400 before. See `docs/routing.md#absolute-form-targets`.
- Document the request ID as a non-secret correlation value everywhere it is exposed: the `X-Request-ID` header, the `requestId` member of problem bodies, log lines, the CORS exposure example and the `Context.execution()` and `ExecutionContext.requestId()` Javadoc. IDs stay a per-process random prefix plus a counter, so a later ID can be predicted from an earlier one; nothing in the framework treats an ID as a capability, and `docs/execution.md` tells applications to use their own `SecureRandom` value for tokens.
- Remove the cross-module helpers from the public API. `Response.validateStatus` and `ExecutionContext.validateTimeout` are no longer public, and the public `com.jsgalactic.axiom.internal.OwnedBodies` factory (which could break `Body` immutability from any classpath code) is gone. The listener now fills a `Body.Builder`, a small public type that owns its array until `build()` and never exposes it, so a request body is still copied exactly once, from the network buffer into the array that becomes the body. **Breaking (pre-release):** code that called the removed methods or `OwnedBodies` must use `Response.of`, `ExecutionContext.create` and `Body.of` or `Body.builder`. `Body` also documents the memory cost of each access pattern and a test measures it (`docs/bodies.md`).
- Add a Checkstyle gate: `checkstyleMain` and `checkstyleTest` run in every Java module's `check` with zero warnings allowed, using the shared ruleset `config/checkstyle/checkstyle.xml` (whitespace, imports, naming, indentation, class design, Javadoc on public library API). The ruleset follows the existing style; a few import blocks and continuation indents were adjusted to match it. See `docs/build.md#code-style`.
- Add a documentation site built from `README.md` and `docs/*.md` with a dependency-free Markdown converter in `build-logic`, plus the aggregated Javadoc of the published modules (`./gradlew docsSite`, output `build/site`). `check` now fails on a broken link or anchor in the documentation (`checkDocsLinks`). A new Docs workflow builds the site for pull requests and deploys it to GitHub Pages from `main`. See `docs/site.md`.
- Add TLS for the HTTP/1.1 listener. `ListenerOptions.tls(TlsOptions)` serves HTTPS with PEM certificate chain and PKCS#8 key files or an `SSLContext` supplier, TLS 1.2 minimum (TLS 1.3 preferred), restricted AEAD cipher suites, ALPN `http/1.1` only, and opt-in mutual TLS with a trust file. Missing, malformed, mismatched or expired material fails startup with a `TlsConfigurationException` that never contains key material. `Server.reloadTls()` and the optional `reloadInterval` swap the material atomically for new connections only. `ListenerOptions.handshakeTimeout` (10 seconds by default) bounds handshakes; a stalled, garbage or plain-text client is closed and frees its connection slot without touching admission. New metrics `axiom.http.tls.handshakes` and `axiom.http.tls.reloads` (tag `outcome`, fixed values). `Request.isSecure()`, `scheme()` and `withTls` expose the connection's scheme, and `TrustedProxies` now falls back to it instead of always `http`. **Binary incompatible (pre-release):** `Request` gained a seventh record component (`tls`; the six-argument constructor remains) and `Server` gained the default method `reloadTls()`. See `docs/tls.md`.
- Bound the request body bytes a listener holds at once with the new `ListenerOptions.maxInFlightBodyBytes` (64 MiB by default). Bodies are reserved when their head is accepted (a declared Content-Length in full, a chunked body as it grows) and returned when the request's response is final or its connection ends; a request that does not fit is answered 503 and its connection closes. This replaces the per-listener worst case of `128 × 3 × maxRequestBody`. A listener whose budget is smaller than the application's `maxRequestBody` refuses to start with `IllegalArgumentException`. See `docs/bodies.md` and `docs/http.md#listener-options`.
- Add the opt-in `Application.closeOnJvmShutdown()`, which closes the application and waits for its listeners to drain, within their shutdown grace periods, when the JVM begins to shut down (for example on `SIGTERM` from a container runtime). Nothing is registered unless it is called. **Binary incompatible (pre-release):** `Application` gained this method. See `docs/http.md#shutdown-on-sigterm`; the REST example uses it.
- Expire queued requests promptly when their own execution deadline is shorter than the queue wait of the request ahead of them. Waiting requests are now ordered by expiry, so each completion or refused submission fails every expired request at a logarithmic cost per request, without scanning the queue (`docs/admission.md`).
- Report listener connections as the gauge `axiom.http.connections` (tag `state` = `open` or `lingering`) and document the real maximum of open sockets (`maxConnections + maxLingeringConnections`, 160 by default) with file-descriptor and load-balancer sizing guidance in `docs/http.md` and `docs/execution.md`.
- Bound the write of the interim `100 Continue` by the listener's `responseTimeout`, so a client that never reads it loses the connection after that bound instead of holding it until the inactivity timeout. Lingering after a response keeps its configurable quiet period (`lingerQuietTimeout`); `docs/http.md` now says how to size it for slow uploaders.
- Load JWT verification keys from a JSON Web Key Set: `JwtAuthenticator.Builder.jwks(JwksSource[, JwksOptions])` with `JwksSource.url` (`java.net.http`, https or loopback http, redirects never followed, 200 and JSON content type only, bounded size and whole-exchange timeout), `JwksSource.file`, or any custom source. Sets are fetched lazily, cached, refreshed when stale and when a token names an unknown `kid` (rate limited), keep the last good set when a fetch fails (until `maxStale`), and bind each key to its declared algorithm with the same size and curve checks as static keys. `JwtAuthenticator.refreshKeys()` fetches on demand. See `docs/security.md`.
- Expose further verified JWT claims and add a revocation and `jti` replay hook. `SecurityIdentity` gained `attributes()` (text, validated and bounded), `attribute(name)` and `withAttributes`; the three-argument constructor remains. `JwtAuthenticator.Builder` gained `exposeClaims(names...)`, `attributes(fn)` over the typed, JSON-free `JwtClaims`, and `tokenCheck(TokenCheck)`, which runs after signature, time, issuer, audience and subject checks and answers 401 `invalid_token` when it returns false; other exceptions fail the request (500). **Binary incompatible (pre-release):** `SecurityIdentity` has a fourth record component. See `docs/security.md`.
- Verify RSASSA-PSS (`PS256`, `PS384`, `PS512`) and EdDSA (Ed25519) JWTs in `axiom-security-jwt` with the same key and algorithm binding as the other algorithms (RSA at least 2048 bits, RFC 7518 salt lengths and hashes, 64-byte Ed25519 signatures, Ed448 refused). Encrypted tokens (JWE) stay unsupported by decision and are rejected with 401 `invalid_token`; the decision is recorded in `docs/security.md`. `JwsAlgorithm` gained constants.
- Add `Cors` middleware to `axiom-security`: a strict origin allow-list (exact `http(s)://host[:port]`, no wildcard with credentials, rejected when built), preflight answers on top of the automatic `OPTIONS` (method must be configured and routed, requested headers configured), `Vary: Origin`, credentials, exposed headers and max-age. See `docs/security.md#cors`.
- Read the RFC 7239 `Forwarded` header and `X-Forwarded-Host`/`X-Forwarded-Port` in `TrustedProxies`: `reading(ForwardedHeaders)` selects one header family (never both), `Forwarded` is parsed strictly and walked right to left with the same trusted-peer rule and hop bound, and `ClientOrigin` gained validated `host()` and `port()` (the three-argument constructor remains). **Binary incompatible (pre-release):** `ClientOrigin` has two more record components. See `docs/security.md`.
- Document the codec registry: codecs are selected by exact lowercase `type/subtype` with no priority, wildcard or structured-suffix matching; two codecs declaring one type fail startup naming both; instances are created once and shared across requests, so `BodyCodec` implementations must be thread-safe. A declaration containing a wildcard such as `application/*` now fails startup as an invalid media type.
- Test and document Accept parsing limits: up to 64 media ranges are parsed, more than 64 or a malformed header is treated as absent, with boundary and real-client header tests.
- Document `LengthRequiredException` (411) as an endpoint's refusal of requests without a declared length, with a live-listener test; the listener itself still never answers 411.
- Report violations of the whole value with an empty field instead of `_root`. **Breaking (pre-release):** `Violation` accepts an empty field, `FieldPath.ROOT` is now the empty string, and problem responses leave the `field` member out of such violations (`{"violations":[{"code":"not_null"}]}`). `DecodeException` still requires a non-empty field when one is given.
- Jakarta adapter: add tests for group sequences passed to `JakartaValidation.create` and for a class-level `@GroupSequence` redefining the default group, document that executable (method) validation is out of scope, and document the provider's `HV000271` warning for `@Valid` on a container.
- Test `Context.validatedBody` with the real JSON codec and the Jakarta adapter through `TestClient` and a live listener.
- JSON decoding reports the first problem in document order (an integer overflow before a duplicate key is `type_mismatch`, the reverse is `duplicate_field`), and invalid UTF-8 is positioned at the offending byte rather than taking precedence over an earlier problem. `docs/bodies.md` gains a migration table from default Jackson behavior to the strict rules (exact enum names, canonical UUIDs, ISO-8601 strings for `java.time`, base64 for `byte[]`, `BigDecimal` for untyped numbers, no scalar coercion, UTF-8 only).
- Add typed parameter accessors `Context.queryInt`, `queryLong`, `queryUuid`, `pathInt`, `pathLong` and `pathUuid`; strict parsing, and a value that does not convert answers 400 with code `invalid_query_parameter` or `invalid_path_parameter` without echoing input.
- Customise the router's own 404, 405 and 501 answers with `Application.notFound`, `methodNotAllowed` and `notImplemented` handlers instead of middleware; the 405 `Allow` header is always preserved. **Binary incompatible (pre-release):** `Application` gained these three methods.
- Add `Application.recognizeMethods(...)` to declare extension methods that no route has, so they are answered 404 rather than 501 on unrouted paths. **Binary incompatible (pre-release):** `Application` gained `recognizeMethods(String...)`.
- Add `Context.automaticOptions()` so an explicit OPTIONS route, such as a wildcard preflight handler, can answer the requests it does not handle with the automatic 204 and accurate `Allow` list.
- List `OPTIONS` in the `Allow` header of 405 responses, since every routed path answers it (RFC 9110 section 15.5.6); the list now equals the automatic OPTIONS answer.
- Add `ListenerOptions` and `Application.listen(address, options)` to configure the shutdown grace period, the connection cap and lingering pool, pipeline depth, request line and header limits, I/O threads, and the idle, head, response and linger timeouts of a listener. Every setting has a validated range and keeps its previous default, so `listen(address)` and `listen(port)` behave as before; connections over the cap are still closed without a response, now documented next to admission. **Binary incompatible (pre-release):** `HttpTransportProvider` gained `bind(Application, InetSocketAddress, ListenerOptions)`, which providers must implement (the two-argument `bind` is now a default method), and `Application.listen(InetSocketAddress)` is now a default method. See `docs/http.md#listener-options`.
- Add streaming responses and server-sent events. `Response.stream(status, contentType, [maxBytes,] body)` sends a body that the handler writes through a `BodyWriter` on its own virtual thread, and `Response.sse(body)` streams `text/event-stream` with `ServerSentEvent` and `EventSink` (`Cache-Control: no-store, no-transform`, `X-Accel-Buffering: no`, a keep-alive comment, CR/LF in data split into data lines, CR/LF in names and ids rejected). The listener sends them with chunked encoding on HTTP/1.1 and holds the handler back while the client is not reading; a stream is limited by a byte cap (64 MiB by default), the request deadline and a 30-second stall bound. A client disconnect, an exceeded cap, a deadline, a handler exception or listener shutdown throws `StreamAbortedException` from the writer and closes the connection without a second response; closing a listener cancels open streams immediately. HEAD gets the head only. New metrics: `axiom.http.streams` (tag `outcome`, six fixed values), `axiom.http.stream.bytes`, `axiom.http.streams.active` and `axiom.http.stream.backpressure`. `TestClient.stream(request)` returns a `StreamedResponse` to read chunks one at a time with a one-chunk hand-off, and `execute` collects finite streams. See `docs/streaming.md`.
- Add observability: a dependency-free `Metrics` SPI in core with `Application.metrics(...)`; the dispatcher records requests by method, route template and status class, latency, admission rejections, queue wait and active and queued depth (no raw paths or user input as tags); the opt-in `axiom-metrics` module with a bounded in-memory `MetricsRegistry` and `PrometheusText` renderer and handler; `Health` and `HealthCheck` for liveness and readiness with `/health/live` and `/health/ready` routes and `beginDrain()`; and a strictly parsed W3C `traceparent` as `Context.traceContext()`. **Binary incompatible (pre-release):** `Application` gained `metrics(Metrics)` and `metrics()`. See `docs/observability.md`.
- Add opt-in security modules: `axiom-security` (Authenticator SPI, `authenticate`/`authenticated`/`hasRole`/`hasAnyRole`/`hasPermission` policies answering 401 or 403, trusted-proxy client addresses, header redaction, secure default response headers) and `axiom-security-jwt` (strict JDK-only JWT bearer authenticator for HS, RS and ES algorithms). Core gains `SecurityIdentity`, `Context.identity()` and the set-once `Context.identity(SecurityIdentity)`.

- Add `Context.validatedBody(type, validator)` with core's `BodyValidator`, which axiom-validation's `Validator` now extends.
- Map exceptions to responses with `app.error(type, handler)`; the nearest registered superclass wins, problem responses stay the default for AxiomException, and a failing error handler produces the generic 500.
- Add middleware (`app.use`, route-level arguments) and route groups with path prefixes and scoped middleware, composed once at startup; global middleware also wrap 404, 405, automatic OPTIONS and 501 answers. **Binary incompatible (pre-release):** `route`, `get`, `post`, `put`, `patch`, `delete`, `head` and `options` moved to the new `RouteGroup` interface and gained a trailing `Middleware...` parameter. Existing source compiles unchanged, but code compiled against the previous `Application` methods must be recompiled.
- Answer OPTIONS for routed paths and `OPTIONS *` automatically with 204 and Allow, refuse TRACE and CONNECT routes, answer CONNECT with 501 everywhere, answer unrecognized methods on unrouted paths with 501, and document every method in one table.
- Send no body with listener errors for HEAD requests.
- Add opt-in validation modules: annotation-free rules in axiom-validation and a Jakarta Validation adapter in axiom-validation-jakarta, reported as 422 field violations.
- Add the `io.axiom:axiom` starter, Maven publication (binary, sources, Javadoc, POM, Gradle module metadata) with optional signing, and the BOM covering all published modules.
- Add consumer compatibility builds (Gradle Kotlin, Gradle Groovy, Maven) behind `./gradlew compatibilityTest`, a scheduled compatibility workflow and a release workflow skeleton.
- Enforce Gradle dependency verification and add a release guide.
- Answer path captures that ctx.pathDecoded cannot decode with 400 invalid_path_encoding instead of 500.
- Send the GET representation's Content-Length on successful HEAD responses.
- Retain the request query and read decoded parameters with ctx.query(name) and ctx.queryAll(name).
- Read bounded request bodies (Content-Length, chunked, Expect: 100-continue) with a configurable limit.
- Add a codec SPI, a strict Jackson JSON codec in axiom-json, and Context.body/json.
- Answer errors with application/problem+json bodies and add exceptions for common 4xx/5xx statuses.
- Map transport failures to 408, 413, 414, 417, 431, 501 and 505.
- Send request bodies from TestClient and add a JSON notes API example.
- Compile route templates with named parameters, terminal wildcards, and deterministic precedence.
- Detect ambiguous route shapes at startup and expose raw captures through the request context.
- Add routing correctness coverage and an opt-in JMH dispatch benchmark.
- Add application creation, exact-path registration, lifecycle controls, and in-memory execution.
- Add request/response contracts, an in-memory test client, and a runnable Hello World example.
- Bootstrap the Java 21 Gradle multi-project build.
