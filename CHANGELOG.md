# Changelog

## Unreleased

- Add JMH benchmarks for the lock-free request path and request ID generation under several threads (`RequestPathBenchmark`, `RequestIdBenchmark`) and for the dispatch overhead of 0, 1, 5 and 20 middleware, global or on the route, with allocation per request through `-prof gc` (`MiddlewareChainBenchmark`). They compile in `check` and run only on request. `docs/benchmarks.md` gains the run commands and a methodology note; no results are published.
- Add a Checkstyle gate: `checkstyleMain` and `checkstyleTest` run in every Java module's `check` with zero warnings allowed, using the shared ruleset `config/checkstyle/checkstyle.xml` (whitespace, imports, naming, indentation, class design, Javadoc on public library API). The ruleset follows the existing style; a few import blocks and continuation indents were adjusted to match it. See `docs/build.md#code-style`.
- Add a documentation site built from `README.md` and `docs/*.md` with a dependency-free Markdown converter in `build-logic`, plus the aggregated Javadoc of the published modules (`./gradlew docsSite`, output `build/site`). `check` now fails on a broken link or anchor in the documentation (`checkDocsLinks`). A new Docs workflow builds the site for pull requests and deploys it to GitHub Pages from `main`. See `docs/site.md`.
- Add TLS for the HTTP/1.1 listener. `ListenerOptions.tls(TlsOptions)` serves HTTPS with PEM certificate chain and PKCS#8 key files or an `SSLContext` supplier, TLS 1.2 minimum (TLS 1.3 preferred), restricted AEAD cipher suites, ALPN `http/1.1` only, and opt-in mutual TLS with a trust file. Missing, malformed, mismatched or expired material fails startup with a `TlsConfigurationException` that never contains key material. `Server.reloadTls()` and the optional `reloadInterval` swap the material atomically for new connections only. `ListenerOptions.handshakeTimeout` (10 seconds by default) bounds handshakes; a stalled, garbage or plain-text client is closed and frees its connection slot without touching admission. New metrics `axiom.http.tls.handshakes` and `axiom.http.tls.reloads` (tag `outcome`, fixed values). `Request.isSecure()`, `scheme()` and `withTls` expose the connection's scheme, and `TrustedProxies` now falls back to it instead of always `http`. **Binary incompatible (pre-release):** `Request` gained a seventh record component (`tls`; the six-argument constructor remains) and `Server` gained the default method `reloadTls()`. See `docs/tls.md`.
- Bound the request body bytes a listener holds at once with the new `ListenerOptions.maxInFlightBodyBytes` (64 MiB by default). Bodies are reserved when their head is accepted (a declared Content-Length in full, a chunked body as it grows) and returned when the request's response is final or its connection ends; a request that does not fit is answered 503 and its connection closes. This replaces the per-listener worst case of `128 × 3 × maxRequestBody`. A listener whose budget is smaller than the application's `maxRequestBody` refuses to start with `IllegalArgumentException`. See `docs/bodies.md` and `docs/http.md#listener-options`.
- Add the opt-in `Application.closeOnJvmShutdown()`, which closes the application and waits for its listeners to drain, within their shutdown grace periods, when the JVM begins to shut down (for example on `SIGTERM` from a container runtime). Nothing is registered unless it is called. **Binary incompatible (pre-release):** `Application` gained this method. See `docs/http.md#shutdown-on-sigterm`; the REST example uses it.
- Expire queued requests promptly when their own execution deadline is shorter than the queue wait of the request ahead of them. Waiting requests are now ordered by expiry, so each completion or refused submission fails every expired request at a logarithmic cost per request, without scanning the queue (`docs/admission.md`).
- Report listener connections as the gauge `axiom.http.connections` (tag `state` = `open` or `lingering`) and document the real maximum of open sockets (`maxConnections + maxLingeringConnections`, 160 by default) with file-descriptor and load-balancer sizing guidance in `docs/http.md` and `docs/execution.md`.
- Bound the write of the interim `100 Continue` by the listener's `responseTimeout`, so a client that never reads it loses the connection after that bound instead of holding it until the inactivity timeout. Lingering after a response keeps its configurable quiet period (`lingerQuietTimeout`); `docs/http.md` now says how to size it for slow uploaders.
- Load JWT verification keys from a JSON Web Key Set: `JwtAuthenticator.Builder.jwks(JwksSource[, JwksOptions])` with `JwksSource.url` (`java.net.http`, https or loopback http, redirects never followed, 200 and JSON content type only, bounded size and whole-exchange timeout), `JwksSource.file`, or any custom source. Sets are fetched lazily, cached, refreshed when stale and when a token names an unknown `kid` (rate limited), keep the last good set when a fetch fails (until `maxStale`), and bind each key to its declared algorithm with the same size and curve checks as static keys. `JwtAuthenticator.refreshKeys()` fetches on demand. See `docs/security.md`.
- Expose further verified JWT claims and add a revocation and `jti` replay hook. `SecurityIdentity` gained `attributes()` (text, validated and bounded), `attribute(name)` and `withAttributes`; the three-argument constructor remains. `JwtAuthenticator.Builder` gained `exposeClaims(names...)`, `attributes(fn)` over the typed, JSON-free `JwtClaims`, and `tokenCheck(TokenCheck)`, which runs after signature, time, issuer, audience and subject checks and answers 401 `invalid_token` when it returns false; other exceptions fail the request (500). **Binary incompatible (pre-release):** `SecurityIdentity` has a fourth record component. See `docs/security.md`.
- Verify RSASSA-PSS (`PS256`, `PS384`, `PS512`) and EdDSA (Ed25519) JWTs in `axiom-security-jwt` with the same key and algorithm binding as the other algorithms (RSA at least 2048 bits, RFC 7518 salt lengths and hashes, 64-byte Ed25519 signatures, Ed448 refused). Encrypted tokens (JWE) stay unsupported by decision and are rejected with 401 `invalid_token`; the decision is recorded in `docs/security.md`. `JwsAlgorithm` gained constants.
- Add `Cors` middleware to `axiom-security`: a strict origin allow-list (exact `http(s)://host[:port]`, no wildcard with credentials, rejected when built), preflight answers on top of the automatic `OPTIONS` (method must be configured and routed, requested headers configured), `Vary: Origin`, credentials, exposed headers and max-age. See `docs/security.md#cors`.
- Read the RFC 7239 `Forwarded` header and `X-Forwarded-Host`/`X-Forwarded-Port` in `TrustedProxies`: `reading(ForwardedHeaders)` selects one header family (never both), `Forwarded` is parsed strictly and walked right to left with the same trusted-peer rule and hop bound, and `ClientOrigin` gained validated `host()` and `port()` (the three-argument constructor remains). **Binary incompatible (pre-release):** `ClientOrigin` has two more record components. See `docs/security.md`.
- Document the codec registry: codecs are selected by exact lowercase `type/subtype` with no priority, wildcard or structured-suffix matching; two codecs declaring one type fail startup naming both; instances are created once and shared across requests, so `BodyCodec` implementations must be thread-safe. A declaration containing a wildcard such as `application/*` now fails startup as an invalid media type.
- Test and document Accept parsing limits: up to 64 media ranges are parsed, more than 64 or a malformed header is treated as absent, with boundary and real-client header tests.
- Document `LengthRequiredException` (411) as an endpoint's refusal of requests without a declared length, with a live-listener test; the listener itself still never answers 411.
- Report violations of the whole value with an empty field instead of `_root`. **Breaking (pre-release):** `Violation` accepts an empty field, `FieldPath.ROOT` is now the empty string, and problem responses leave the `field` member out of such violations (`{"violations":[{"code":"not_null"}]}`). `DecodeException` still requires a non-empty field when one is given.
- Jakarta adapter: add tests for group sequences passed to `JakartaValidation.create` and for a class-level `@GroupSequence` redefining the default group, document that executable (method) validation is out of scope, and document the provider's `HV000271` warning for `@Valid` on a container.
- Test `Context.validatedBody` with the real JSON codec and the Jakarta adapter through `TestClient` and a live listener.
- JSON decoding reports the first problem in document order (an integer overflow before a duplicate key is `type_mismatch`, the reverse is `duplicate_field`), and invalid UTF-8 is positioned at the offending byte rather than taking precedence over an earlier problem. `docs/bodies.md` gains a migration table from default Jackson behavior to the strict rules (exact enum names, canonical UUIDs, ISO-8601 strings for `java.time`, base64 for `byte[]`, `BigDecimal` for untyped numbers, no scalar coercion, UTF-8 only).
- Add typed parameter accessors `Context.queryInt`, `queryLong`, `queryUuid`, `pathInt`, `pathLong` and `pathUuid`; strict parsing, and a value that does not convert answers 400 with code `invalid_query_parameter` or `invalid_path_parameter` without echoing input.
- Customise the router's own 404, 405 and 501 answers with `Application.notFound`, `methodNotAllowed` and `notImplemented` handlers instead of middleware; the 405 `Allow` header is always preserved. **Binary incompatible (pre-release):** `Application` gained these three methods.
- Add `Application.recognizeMethods(...)` to declare extension methods that no route has, so they are answered 404 rather than 501 on unrouted paths. **Binary incompatible (pre-release):** `Application` gained `recognizeMethods(String...)`.
- Add `Context.automaticOptions()` so an explicit OPTIONS route, such as a wildcard preflight handler, can answer the requests it does not handle with the automatic 204 and accurate `Allow` list.
- List `OPTIONS` in the `Allow` header of 405 responses, since every routed path answers it (RFC 9110 section 15.5.6); the list now equals the automatic OPTIONS answer.
- Add `ListenerOptions` and `Application.listen(address, options)` to configure the shutdown grace period, the connection cap and lingering pool, pipeline depth, request line and header limits, I/O threads, and the idle, head, response and linger timeouts of a listener. Every setting has a validated range and keeps its previous default, so `listen(address)` and `listen(port)` behave as before; connections over the cap are still closed without a response, now documented next to admission. **Binary incompatible (pre-release):** `HttpTransportProvider` gained `bind(Application, InetSocketAddress, ListenerOptions)`, which providers must implement (the two-argument `bind` is now a default method), and `Application.listen(InetSocketAddress)` is now a default method. See `docs/http.md#listener-options`.
- Add streaming responses and server-sent events. `Response.stream(status, contentType, [maxBytes,] body)` sends a body that the handler writes through a `BodyWriter` on its own virtual thread, and `Response.sse(body)` streams `text/event-stream` with `ServerSentEvent` and `EventSink` (`Cache-Control: no-store, no-transform`, `X-Accel-Buffering: no`, a keep-alive comment, CR/LF in data split into data lines, CR/LF in names and ids rejected). The listener sends them with chunked encoding on HTTP/1.1 and holds the handler back while the client is not reading; a stream is limited by a byte cap (64 MiB by default), the request deadline and a 30-second stall bound. A client disconnect, an exceeded cap, a deadline, a handler exception or listener shutdown throws `StreamAbortedException` from the writer and closes the connection without a second response; closing a listener cancels open streams immediately. HEAD gets the head only. New metrics: `axiom.http.streams` (tag `outcome`, six fixed values), `axiom.http.stream.bytes`, `axiom.http.streams.active` and `axiom.http.stream.backpressure`. `TestClient.stream(request)` returns a `StreamedResponse` to read chunks one at a time with a one-chunk hand-off, and `execute` collects finite streams. See `docs/streaming.md`.
- Add observability: a dependency-free `Metrics` SPI in core with `Application.metrics(...)`; the dispatcher records requests by method, route template and status class, latency, admission rejections, queue wait and active and queued depth (no raw paths or user input as tags); the opt-in `axiom-metrics` module with a bounded in-memory `MetricsRegistry` and `PrometheusText` renderer and handler; `Health` and `HealthCheck` for liveness and readiness with `/health/live` and `/health/ready` routes and `beginDrain()`; and a strictly parsed W3C `traceparent` as `Context.traceContext()`. **Binary incompatible (pre-release):** `Application` gained `metrics(Metrics)` and `metrics()`. See `docs/observability.md`.
- Add opt-in security modules: `axiom-security` (Authenticator SPI, `authenticate`/`authenticated`/`hasRole`/`hasAnyRole`/`hasPermission` policies answering 401 or 403, trusted-proxy client addresses, header redaction, secure default response headers) and `axiom-security-jwt` (strict JDK-only JWT bearer authenticator for HS, RS and ES algorithms). Core gains `SecurityIdentity`, `Context.identity()` and the set-once `Context.identity(SecurityIdentity)`.
- Expose the connection's peer as `Request.remoteAddress()` (set by the HTTP listener, `null` in memory) with `Request.withRemoteAddress`. `Request` gained a sixth record component; the five-argument constructor remains.
- Rename the Java packages and the Maven group from `io.axiom` to `com.jsgalactic.axiom` (the starter is now `com.jsgalactic.axiom:axiom`; artifact IDs are unchanged). Nothing had been published under `io.axiom`.
- Add `Context.validatedBody(type, validator)` with core's `BodyValidator`, which axiom-validation's `Validator` now extends.
- Map exceptions to responses with `app.error(type, handler)`; the nearest registered superclass wins, problem responses stay the default for AxiomException, and a failing error handler produces the generic 500.
- Add middleware (`app.use`, route-level arguments) and route groups with path prefixes and scoped middleware, composed once at startup; global middleware also wrap 404, 405, automatic OPTIONS and 501 answers. **Binary incompatible (pre-release):** `route`, `get`, `post`, `put`, `patch`, `delete`, `head` and `options` moved to the new `RouteGroup` interface and gained a trailing `Middleware...` parameter. Existing source compiles unchanged, but code compiled against the previous `Application` methods must be recompiled.
- Answer OPTIONS for routed paths and `OPTIONS *` automatically with 204 and Allow, refuse TRACE and CONNECT routes, answer CONNECT with 501 everywhere, answer unrecognized methods on unrouted paths with 501, and document every method in one table.
- Send no body with listener errors for HEAD requests.
- Add opt-in validation modules: annotation-free rules in axiom-validation and a Jakarta Validation adapter in axiom-validation-jakarta, reported as 422 field violations.
- Add the `io.axiom:axiom` starter, Maven publication (binary, sources, Javadoc, POM, Gradle module metadata) with optional signing, and the BOM covering all published modules.
- Add consumer compatibility builds (Gradle Kotlin, Gradle Groovy, Maven) behind `./gradlew compatibilityTest`, a scheduled compatibility workflow and a release workflow skeleton.
- Enforce Gradle dependency verification and add a release guide.
- Answer path captures that ctx.pathDecoded cannot decode with 400 invalid_path_encoding instead of 500.
- Send the GET representation's Content-Length on successful HEAD responses.
- Retain the request query and read decoded parameters with ctx.query(name) and ctx.queryAll(name).
- Read bounded request bodies (Content-Length, chunked, Expect: 100-continue) with a configurable limit.
- Add a codec SPI, a strict Jackson JSON codec in axiom-json, and Context.body/json.
- Answer errors with application/problem+json bodies and add exceptions for common 4xx/5xx statuses.
- Map transport failures to 408, 413, 414, 417, 431, 501 and 505.
- Send request bodies from TestClient and add a JSON notes API example.
- Compile route templates with named parameters, terminal wildcards, and deterministic precedence.
- Detect ambiguous route shapes at startup and expose raw captures through the request context.
- Add routing correctness coverage and an opt-in JMH dispatch benchmark.
- Add application creation, exact-path registration, lifecycle controls, and in-memory execution.
- Add request/response contracts, an in-memory test client, and a runnable Hello World example.
- Bootstrap the Java 21 Gradle multi-project build.
